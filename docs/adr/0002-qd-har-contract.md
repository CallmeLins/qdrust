# ADR-0002：QD HAR 外部兼容契约

- 状态：Accepted
- 日期：2026-08-17

## 决策

不兼容旧数据库和内部 API，但旧 QD 导出的 HAR 必须无损导入、再次导出并保持执行语义。原始 JSON 与强类型执行视图同时保存，未知字段不得丢失。契约来源为旧 QD `Fetcher` 行为、内置模板和脱敏真实 fixture。

## 后果

原生 v1 模板与 `qd_har` 使用不同 source format。无法支持的语义必须产生诊断，禁止静默转换。安全边界优先于旧 QD 的危险默认值，差异必须可配置且有文档。

### 正则（2026-09-23 补充，2026-09-24 修订）

`re` 字段先交给 Rust 的线性引擎（`regex`）。它不回溯，任何 pattern 都拖不进指数时间，但 Python 的 lookaround 和反向引用它没有 —— 而那是旧 QD 的合法写法。所以线性引擎拒绝时才交给回溯引擎（`fancy-regex`，MIT），并给它固定上限（1000000 步）：超出上限**报错**，不当作「不匹配」，因为引擎没走到的结论不能当成结论。回溯路径因此只由线性引擎拒掉的 pattern 进入。

上限之外还开了回溯引擎的 `seek` 预过滤。上限管得住回溯，却管不住「在响应体的每个位置都重扫一遍」，而 `(?s)(?=.*…)` 这类断言正是这么写的：不加预过滤时 Linux_SB.har 的断言对 100 KB 响应体要 63.8 s 才回「不匹配」，而这恰是调度中最常见的失效响应（会话过期的错误页），在运行日志里与挂死无异。`seek` 先拿模式的一个保守近似跳过不可能的位置，同一响应体降到毫秒级。该近似是**保守**的：可以多给候选位置，不会漏掉可匹配的位置，因此不会把正确答案改错；能因它改变的只有「本来要耗尽上限」那一类 —— 以字面量结尾的模式碰上不含该字面量的响应体，原报「放弃」，现直接给出正确的「不匹配」，方向是变准。这一点不靠机制本身的说明取信：开/关 `seek` 把全部 6280 条用例逐条跑通比对为 0 差异，且关掉它时那条性能测试确实以 66.49 s 撞破上限而失败。

`/模式/flags` 的 flags 按旧 QD 自己的解析器解释（`libs/fetcher.py::run_rule`，`g` 是 findall/search 的选择而非引擎 flag，`x` 不在其 flag 集内），`u` 恒为 Unicode —— Python 3 的 `re.U` 是 no-op，不存在「`u` 表示关掉 Unicode」的读法。

Python 与 Rust 的**方言**差异在编译前按 Python 的读法翻译：不成形的 `{` 转义成 `\{`（`{"total":(\d+)` 这类 JSON 提取在 Python 里是字面量），`{,n}` / `{,}` 补成 `{0,n}` / `{0,}`，`\Z` 写成 `\z`，反斜杠后的标点还原成标点本身（`\<` 是 `<`），类内的 `[` 转义成 `\[`（Python 没有 POSIX 类）。翻译只改写法、不改语义，因此不产生诊断；这是方言适配，不是静默转换。

另有三处**刻意拒绝**，因为翻译只能靠猜，而猜错会匹配到错的文本而不是失败：`{m,n}` 里 `m > n`（Python 是语法错，回溯引擎当成能匹配）、`\N{...}`（Python 是命名字符，回溯引擎读成「非换行」）、以及反斜杠 + Python 不认的字母（白名单 `abfnrtvdDsSwWABZNxuU` 之外一律拒，一次堵掉 `\h` `\R` `\G` `\X` `\p{…}` `\K` 这批回溯引擎认而 Python 不认的词）。

语料是这条线的判据：387 个模板共 6182 条 `re`，改动前 62 条被拒，现在 6181 条可编译（余下 1 条 `[^]` 在 Python 里也是「未闭合字符集」，两引擎一致拒绝，属模板自身笔误）；用 Python 的 `re` 双向差分，两个方向都是 0 分歧。**仍然不同的**只剩模板库里不出现、且 Python 侧判为错误的那几条（这里拒绝：`\ooo`、`(?a)`；这里多接受：`a**`、`a(?i)b`、`(?<name>x)`、非法或重名的捕获组名），写法、flags、返回形状与这条边界见 [参考 · 与旧 QD 的兼容范围](../reference.md)。
