# 使用

> 返回 [README](../README.md)

## 导入 QD HAR 模板

- 在 WebUI 的模板页点击导入，选择从旧 QD 导出的 `*.har.json`。
- 导入时会校验并**保留原始 HAR JSON**，兼容样本见 `tests/fixtures`。
- 也可用命令行校验：

```powershell
cargo run -p qdrust-cli -- validate .\template.har.json
```

### 模板变量是怎么算出来的

基于模板新建任务时，WebUI 会按 QD `HARSave.get_variables` 的语义列出需要填写的变量（`GET /api/v1/templates` 返回的 `variables` 字段）：

- 只看请求实际读取的名字：method、URL、请求体，以及每个请求头 / Cookie 的名字与值；
- 用 Jinja 解析，所以 **过滤器和函数名不算变量**：`{{jpop_username|urlencode}}` 只产出 `jpop_username`，`{{md5(password)}}` 只产出 `password`；
- **按条目顺序判定**：只有被 `extract_variables` 提取**之后**的引用才不算输入。所以登录后的 `{{token}}` 不会被问，而先喂给 `api://util/gb2312` 再由该条目回写提取的 `{{username}}` 仍然是输入；
- 无法解析的片段（如 `{% while ... %}` 控制条目）不产生变量。

`native_v1` 模板则直接用定义里声明的变量名。

## 原生模板 schema v1

除导入旧 QD HAR 外，也可以直接写 qdrust 原生模板。它是版本化 JSON，**不执行 Python**，顶层必须包含 `version: 1`、非空 `name` 和 `steps`：

```json
{
  "version": 1,
  "name": "Health check",
  "variables": {
    "base_url": "https://example.com"
  },
  "steps": [
    {
      "type": "request",
      "name": "Fetch health",
      "method": "GET",
      "url": "{{base_url}}/health",
      "headers": {"accept": "application/json"}
    },
    {
      "type": "extract",
      "name": "Read status",
      "source": "status",
      "selector": "",
      "target": "status",
      "required": true
    }
  ]
}
```

步骤类型：`request`、`extract`、`if`、`for_each`、`delay`；请求 body 支持 `json`、`text` 和 `form`。表达式与 `api://util/*`、`api://browser/*` 的用法见 [模板表达式与内置工具](expressions.md)。

安全限制：最多 1000 个静态步骤、最多 16 层嵌套、单次 delay 最长 5 分钟；运行时还会独立限制请求数、循环次数、响应体和总时长。

## 创建与运行任务

1. **模板必选**：新建任务时先选模板——任务的请求完全由模板决定（多页模板常混合 GET/POST），任务本身不携带请求方法 / URL / 请求头 / 请求体。
2. 填写变量（模板需要的变量会按 QD 语义自动列出）、配置 cron / 间隔调度。
3. 用「立即运行」手动触发，或在运行记录中查看每一步的请求 / 响应 / 提取变量；支持取消正在执行的运行。
4. 模板页提供两种导入来源：从本地导入 QD HAR，或从订阅的模板库里挑（见[订阅模板库](#订阅模板库汇总与预览)）；挑选是先预览、保存才入库。本站公开模板经 PushRequest 审批后发布。
> 任务只保存「模板 + 变量 + 调度」，任务列表仅展示任务名——请求方法与 URL 在列表里既冗余又难扫读，需要时到任务详情里看（那里仍会镜像模板首条请求）。早于该规则的存量任务（未绑定模板、自带一条请求）编辑时仍会保留「（无模板）」选项与其原有请求。

## 可视化 HAR 编辑器

WebUI 提供可视化编辑器，可直接增删改请求、设置请求头 / 表单 / 鉴权、编写 `success_asserts` 与 `extract_variables`，无需手改 JSON。

## 调度与随机延迟

可视化调度器支持固定间隔与 cron；「随机延迟」可让同一任务的多次执行在时间上打散，避免被目标站点识别为固定节奏。模板变量支持在创建任务时**预填**默认值。

### 时区与夏令时

cron 按每个任务各自的 IANA 时区（`timezone` 字段）求值，**DST 感知**：设 `America/New_York` 的任务，`0 9 * * *` 会全年在当地 09:00 触发，无需为冬令/夏令手改 cron。任务未设 `timezone` 时使用服务端 `QDRUST_DEFAULT_TIMEZONE`（默认 `Asia/Shanghai`）。WebUI 中任务列表与运行历史的「上次运行/开始时间」也按该任务时区展示（未设时区则用查看者浏览器本地时区）。

## 运行日志与历史

每次运行会记录 QD 风格的文本日志；在任务详情页可查看该任务的运行历史，并支持**清空**历史记录。活跃运行的步骤通过 WebSocket 实时推送。

**运行日志总览**（任务页点标题右侧「运行日志」打开的是一个宽弹窗，不是独立页面）把**所有任务**的运行放在一张表里，按时间倒序，可按「全部 / 成功 / 失败」筛选、按任务过滤，能在行内取消或删除，并在弹窗底部用「上一页 / 下一页」翻页（每页条数在弹窗自己的分页条上设置，不与其他列表互相影响，见[列表分页与每页条数](#列表分页与每页条数)）。任务多的时候用它一眼扫完当天所有任务，不必逐个点进任务详情；点任务名可以直接跳到该任务的运行历史。对应接口为 `GET /api/v1/runs`（`status` / `task_id` / `limit` / `before_id` 参数，游标分页）。

## 列表分页与每页条数

任务、订阅、我的模板、公共模板（订阅源汇总）与本站公开模板都按页渲染，**默认每页 10 条**。分页条在表格下方**始终显示，不随列表长短收起**：它是修改每页条数的唯一入口，一旦跟着列表长度收起，选到 100 条之后就再也改不回 10 了。只有一页的列表会隐去中间那段翻页控件，只留左边的总条数与右边的条数选择器。运行日志弹窗同样有条分页条（它是游标分页，所以只显示「第 N 页」，没有总页数，两个按钮始终可用）。

分页条在表格下方：左边是总条数，中间是「上一页 / 第 x / y 页 / 下一页」（列表只有一页时不显示），右边是**每页条数**（10 / 20 / 50 / 100）。**每个列表各记各的条数**，改一个不会动到别的：它们读条数的时机和目的都不一样，共用一份只会让人在改 A 的时候顺手把 B、C 也改了。这个选择按浏览器存在 `localStorage`，键是 `qdrust.pageSize.<列表名>`（`tasks` / `subscriptions` / `templates` / `publicTemplates` / `library` / `runLog`）——它是阅读偏好而不是站点设置，因此不需要服务端状态也不需要管理员权限。旧版用一个共享的 `qdrust.pageSize`，升级时它仍然被读取，作为各列表尚未单独设置过的条数的起点，但不再被写入。除运行日志外，列表数据本来就整份在浏览器里，改条数只影响渲染，不会重新请求；运行日志是服务端分页，改条数会**重新取数并把游标重置回第一页**（旧游标是按旧条数切的，不能复用）。

换了筛选条件就会回到第 1 页（任务页的搜索 / 分组、模板页的搜索、公共模板库的搜索 / 排序 / 切换来源 / 刷新，以及运行日志的状态 / 任务）；列表变短时页码也会自动收回，不会停在已经不存在的页上。运行日志是游标分页，没有「第几页共几页」可回，所以改筛选条件或改每页条数时直接清空游标栈重新取数——旧游标是按上一份结果集切的，留着它只会去问「那份列表的下一页」，而那份列表已经不存在了（这正是「按任务筛选好像没生效」的成因：筛选本身是对的，游标替另一份列表答了话）。**「全选」只覆盖当前页**（任务与公共模板库两处），免得翻页后看不见的行被批量操作带上。

## 订阅模板库（汇总与预览）

支持订阅官方模板库 <https://github.com/qd-today/templates>，以及任何兼容同一规范的第三方库或单个模板文件 URL。库浏览是**模板页内的一块**，不是独立页面：没有整页跳转，也就没有「返回模板」这一步。

1. 在「模板」页点标题右侧的「添加订阅」，弹窗里填订阅名称与库地址（例如 `https://github.com/qd-today/templates`）。没有导入方式的选择：订阅只是登记一个来源目录，**不会**自动把模板拉进本地——官方库里是几百个模板，全量导入会把你自己建的模板淹掉。模板是否导入、何时导入，由你在下方的「公共模板」列表里自己决定。订阅区域在页面标题下、「我的模板」上方（来源排在它供给的列表之前），行内可随时「编辑 / 启用停用 / 删除」，无订阅时该表格显示为空列表。
2. 「公共模板」表默认列出**所有已启用订阅源**的条目（名称、作者、来源、版本、日期、状态），按上游日期倒序，表头可点排序，可搜索名称 / 作者 / 来源。用「订阅源」下拉切到单个来源时，表格多出「订阅源」列，并标出该源是按 `tpls_history.json` 清单读的还是扫描文件得到的。停用的订阅不进汇总。
3. **点行内「导入」是预览，不是直接落库**：服务端把该条目的上游 HAR 取回来但**不落库**，编辑器打开的就是它，改好保存才写进「我的模板」——随手点几行不会在模板列表里留下用不上的东西。已导入且无更新的行显示「打开」，直接编辑本地那份、不联网。
4. 已导入的条目标「已导入」；上游版本变新时标「有更新」，点「更新」同样先预览上游那一版，保存后**原地更新**本地模板（不会生成重名副本），并把来源记录的版本推进到上游版本。
5. 需要一次预载多个时，点工具栏「批量选择」才展开勾选列与批量导入工具条。**批量导入是直接的，不逐个预览**；汇总视图下勾选可以跨来源，服务端按来源分组调用。入口列会随状态在「导入 / 更新 / 打开」之间切一个主操作。

> 命名约定：qd-today 语境里的「公共模板」指**订阅源的汇总**，本页沿用该含义；本站用户互相发布的模板另称「本站公开模板」，默认折叠在页尾。

来源目录有**短缓存**（90 秒，按仓库 URL 而不是按订阅或账号——同一仓库被两个订阅或两个账号指向时只读一次）。汇总视图一次要读所有来源，而每个来源是两三个 GitHub 请求，所以缓存目录本身；「已导入 / 有更新」**不进缓存**，每次都由本地库现算，因此刚订阅完立刻就能看到状态变化。工具栏的「刷新」按钮带 `refresh`，绕过缓存重新读取。

**读取失败不会再把来源清空**：目录抓取最多试 3 次（间隔 300 / 600 毫秒），只重试传输类失败——连接被断、超时、body 传了一半；HTTP 状态码是上游给的答复（比如仓库没有清单时的 404），重试只会拿到同一个。库抓取的单次请求超时是 **60 秒**，比其它请求宽：官方清单有 3 MB 且 93% 是内联 HAR，按 API 调用的默认超时收不完 body。缓存过期后重取仍然失败时，会退回用上一份成功读到的目录并标为「缓存」，而不是把该来源变成 0 条——**只有你主动点「刷新」时才如实报错**，因为那时你问的是「现在是什么样」。

来源的发现规则（与 QD 第三方库规范一致）：

- 仓库根目录有 `tpls_history.json` 时按其清单读取：`har` 以模板名为键，值里的 `author` / `comments` / `version` / `date` / `commenturl` 就是上面展示的元数据；HAR 优先取内联的 base64 `content`，否则按 `url`、再否则按 `filename` 下载。
- 没有清单时回退为扫描仓库树中的 `*.har` / `*.json`，此时条目不携带版本，因此不会提示更新。
- 变量说明（`comments`）在服务端被规整为纯文本，不注入到页面里。
- 上游内容**有两种形状**：标准 HAR（`{log:{entries}}`）和 QD 导出的请求数组（`[{comment, request:{method,url,headers,cookies,data,mimeType}, rule:{…}}]`）——`tpls_history.json` 里的 `content` 就是后者。预览接口按契约原样返回上游文档，所以**转成编辑器认得的 HAR 这一步在前端做**（`harDocumentFrom` / `qdTplToHar`，与本地文件导入共用同一条转换）。服务端的执行链用 `QdHar::parse_qd` 读取，两种形状都吃得下。

来源记录写在 `template_imports`（订阅 + 条目名 → 本地模板 + 上游版本），用于判断「已导入 / 有更新」。删除订阅只删除来源记录，**已导入的模板会保留**（导入是复制到你自己的库，不是软链）。一个读不动的仓库不会让整张表变空：它单独列出错误，其余来源照常显示；条目总数触及上限时列表会说明已被截断。

对应接口：

- `GET /api/v1/library?refresh=<bool>`：所有已启用来源的汇总（`entries` 加上每个来源的 `sources` 结果与错误）。
- `GET /api/v1/subscriptions/{id}/library`：单个来源的目录。
- `GET /api/v1/subscriptions/{id}/library/preview?entry=<名称>`：取出一条的 HAR 但**不落库**。条目名走查询参数而不是路径段，因为它是来源自己起的自由字符串，可能含 `/`。
- `POST /api/v1/subscriptions/{id}/library/apply`：保存编辑器里的 HAR 并写下来源记录；带 `template_id` 则原地更新，否则新建。
- `POST /api/v1/subscriptions/{id}/import`：按名称批量**直接**导入，逐条返回成功 / 更新 / 失败，并给出写入模板的 id 与是否原地更新。

## 命令行（CLI）

校验旧 QD HAR：

```powershell
cargo run -p qdrust-cli -- validate .\template.har.json
```

执行 HAR，并传入变量和整体超时：

```powershell
cargo run -p qdrust-cli -- run .\template.har.json --var token=abc --timeout 60
```

CLI 默认拒绝私网、localhost 和无效 TLS 证书，不继承旧 QD 的宽松网络策略。
