# 推送 / 通知

> 返回 [README](../README.md)

任务成功或失败时，可通过通知渠道推送提醒。系统共支持 **11 种**渠道，在「通知」页新建渠道并绑定到任务即可。

**不只有通知页能绑定。** 两个就近入口：

- **任务列表行内的铃铛**：实心＝该任务已绑至少一个渠道，斜线＝没绑。点一下切换——开着时一键清空该任务的全部绑定，关着时把**所有已启用渠道**各绑一条（默认「失败时」、阈值 1）；一个渠道都没建时会提示先去通知页。列表行还同时从服务端拿 `notification_action_count`，所以状态不靠刷新猜。
- **新建 / 编辑任务弹窗的「开启通知」**：勾上后多选渠道（同样默认「失败时」、阈值 1），建任务和配通知一次完成。保存时只改**差量**：新勾的渠道加绑定，取消勾的渠道删绑定，**仍勾着的渠道不动**，所以通知页里调过的 event / 阈值 / 标题正文模板不会被这个开关覆盖。新建任务时绑定在任务创建之后落库（那时才有任务 id）。

更细的 event / 失败阈值 / 标题正文模板仍在「通知」页的「通知动作」里调。

| 渠道 | 所需配置 | 说明 |
|---|---|---|
| **Webhook** | `url` | 向该 URL `POST` JSON（含 `event` / `task_name` / `run_id` / `http_status` / `error`） |
| **自定义 HTTP** | `url`, `method`(默认 `POST`), `headers`(JSON, 可选), `body`(可选模板) | 完全自定义的请求，可指向自建的 ntfy、Gotify 等；`http` 与 `https` 均可 |
| **Email** | `to` | 经 SMTP 发送，需先配置 `QDRUST_SMTP_*` 环境变量 |
| **Bark** | `url` | iOS 推送，设备地址形如 `https://api.day.app/你的Key` |
| **Server 酱** | `sendkey` | 微信推送 SendKey |
| **Telegram** | `token`, `chat_id`, `host`(可选) | 机器人 token 与 chat id；`host` 可指定自建 API 域名 |
| **钉钉机器人** | `access_token` | 自定义机器人 access_token |
| **WxPusher** | `app_token`, `uid` | 应用 token 与目标 UID |
| **WxPusher SPT** | `spt` | 主题推送码（逗号分隔可多个） |
| **企业微信应用** | `corpid`, `secret`, `agentid`, `to_user`(默认 `@all`), `proxy`(可选) | 自建应用消息；`proxy` 可指定 API 代理 / 自定义域名 |
| **企业微信群机器人** | `key` | 群机器人 webhook key |

通知标题与正文由调度器统一渲染，并在 Email、自定义 HTTP 与推送渠道间共享；单个渠道投递失败只记录日志，不会中断任务执行。

**地址范围**：渠道配置里由你填写的地址（自定义 HTTP 与 Webhook 的 `url`、Telegram 的 `host`、企业微信应用的 `proxy`）和模板运行共用同一道出站闸门——默认只允许公网地址，解析结果是内网 / 回环 / 链路本地时会在发请求**之前**被拒，错误信息里会点名 `security.allow_private_network`。要打内网（自建 ntfy、内网 GitLab 机器人）需在管理页开启[出站请求访问内网地址](usage.md#出站请求访问内网地址高风险开关)；`http` 与 `https` 都允许，但**不跟随重定向**。SMTP 投递与 OIDC 不在其中。

**测试渠道**：通知页每个渠道行都有「测试」按钮，点击会立刻用真实配置发一条测试消息（`POST /api/v1/notification-channels/{id}/test`）。它走的是调度器同一条投递路径，所以测试通过就说明凭据与传输都正常；失败时错误原因会直接显示在提示条里。

**预览动作**：渠道级测试只能验证凭据——标题与正文模板挂在「任务↔渠道」的绑定上，不在渠道上。要检查某个绑定**会说出什么**，在该行点「预览」（`GET /api/v1/notification-actions/{id}/preview`）：服务端按绑定模板 → 你的默认模板 → 内置模板的顺序渲染出标题与正文，**不投递给任何渠道**。默认拿该任务最近一次运行的真实 `{status}` / `{error}` / `{log}`；任务从未运行时响应里 `source` 为 `sample`，这些变量为空，弹窗会直接说明这一点，免得空的 `{log}` 看起来像模板写错了。

**通知动作**（把渠道绑定到任务）还支持：

- **列表按任务聚合**：绑定列表按任务分组，一个任务一行——任务名、渠道 chip（形如 `渠道 · 失败`）、绑定条数；该任务几条绑定的事件/阈值/模板不完全相同时，额外标一个「N 种配置」。多于一条绑定的任务默认折叠，展开后逐条显示，行内可预览 / 编辑 / 删除；只有一个绑定的任务直接展开。行尾的垃圾桶清掉该任务的全部绑定（与任务列表铃铛的「关」是同一个接口），不必回到任务弹窗。
- **列表范围**：下方列表列出你**全部**任务的绑定，和创建表单里勾了哪些任务无关——刚保存的动作不会因为没勾任何任务而消失。勾选只决定「这次新建的动作写到哪些任务」。
- **批量绑定**：一次为多个任务创建同一个动作，不必逐个任务重复配置。
- **失败次数阈值**：连续失败达到阈值后才通知（统计「上次成功之后」的失败次数），过滤偶发网络抖动。
- **仅自动执行时通知**：手动点击「立即运行」不触发，只对定时 / 随机延迟 / 重试触发的运行生效。
- **自定义标题与正文模板**：可用变量 `{event}` `{status_cn}` `{task_id}` `{task}` `{run_id}` `{status}` `{error}` `{log}` `{t}` —— `{status_cn}` 是事件的**中文**说法（成功 / 失败 / 测试；`{event}` 仍是机器值 `success` / `failure`），`{log}` 是 QD 模板的运行日志，`{t}` 是运行完成时间（按任务时区渲染，未设置时区时用 UTC）；未识别的 `{...}` 占位符会原样保留。

**默认通知模板（按账号，每个事件一份）**：通知页的「默认通知模板」区可分别给「成功」和「失败」写一套标题 / 正文（`GET` / `PUT /api/v1/notification-defaults[/{event}]`）。绑定自己没有写模板时就用它，三个层级依次回落：

```
绑定自己的模板  →  你的默认模板（同事件）  →  内置模板
```

所以同一套说法不必在 14 个任务的 28 条绑定里各写一遍；改默认模板只影响没写自己模板的绑定，**已经单独写过的绑定不受影响**。两项都留空即回到内置模板（输入框里的灰色占位符显示的就是内置模板本身，可以直接抄下来改）。

内置模板（最后兜底，`failure` 与 `success` 共用一套）：

```text
[qdrust] Task "{task}" {event}
Task: {task}
Event: {event}
Run: #{run_id}
HTTP status: {status}
Error: {error}
Time: {t}
Log: {log}
```

`{log}` 就在其中——这就是调度器此前不含日志正文的那段默认文案，现在默认也带上了（[#43](https://github.com/CallmeLins/qdrust/issues/43)）。

内置模板现在是一串**模板文本**而不是拼好的字符串，所以它和用户自己写的模板走同一条渲染路径；默认文案的两处措辞与旧版不同：标题里的状态词从 `succeeded` / `failed` 改成与正文一致的机器值 `{event}`（`success` / `failure`），空变量渲染成空串而不是旧的 `-`。想要旧措辞的话，把上面两行抄进「默认通知模板」再改即可。
